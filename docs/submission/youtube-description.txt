HOW IT WORKS
A seller wraps any HTTP API in one command. The service is registered on 0G with its payout address and an accepts[] price list stored in the contract, while the private upstream is mapped by an owner-signed EIP-191 challenge — its URL never touches the chain.

A buyer agent reads the 402 invoice, pays PaymentRouter.pay(serviceId, nonce, payTo), and retries with the transaction hash. The router binds that payment to the invoice nonce on-chain and rejects a replay, so the gateway verifies with one exact log lookup on the receipt: no scanning, no indexer, no facilitator, and the gateway never custodies funds.

Each served call is attested on-chain with its payment hash, so a trust score counts payments that actually settled rather than stars anyone can farm. A call paid by the service's own owner is served but deliberately never scored, so reputation cannot be wash-traded.

WHERE THIS SITS RELATIVE TO x402
AgentGate speaks the x402 V1 envelope — HTTP 402, accepts[], the X-PAYMENT header — so anything that parses an x402 challenge can read one of ours. But the settlement scheme is deliberately named exact-settled, not exact. 0G has no x402 facilitator, so the buyer settles first and presents a transaction hash instead of signing an authorization for a third party. Naming it differently makes a generic x402 client fail fast rather than hang forever. We do not claim compliance we do not have.
