The Galileo deployment landed. AgentGateRegistry (0x2f5b7AaD7bffcEc5B6cda95Af4439494C1D576dA), PaymentRouter (0xfA5e4CC796390Cdca78C6E34664FE77Be1475FBB) and SpendGuard (0x08b4049802999245888E72D0C31Fb4cA55C30E1B) are live on chain 16602; the CLI, MCP server and SDK ship as agentgate-0g on npm; and the gateway serves real 402 invoices priced from the contract's own accepts[] list. The full loop ran between two independent wallets with real OG, not a rehearsal — register 0x4e15b95f5b2c91dc1bf9e112ed78c6418f4f954265c43b9d9f7053d415b2f249, pay 0xebee2bc6d95f505445a49caf8051209256abcbbf4e24c1f00194a7e8eef2a815, attest 0xd0a24968f092826fd90e298dc36acb64d193d3b11c6e11dec951b7c49aa063be. Read the catalog yourself with npx agentgate-0g list; no key, no config, no clone. 460 TypeScript tests and 42 Foundry tests are green on the tip of main.

One surface did not migrate, and stating it is cheaper than being caught: the hosted dashboard still serves the pre-migration build, so the catalog and activity ledger you see in the demo run from the repo. Re-pointing it is first in the queue.

Then: re-seed the reference RWA oracle, since the registry today carries an FX feed and a crypto spot feed rather than the gold-and-FX service the offline demo wraps; an authorization-settled ERC-20 rail, which the on-chain accepts[] list already anticipates and needs no contract change, though a router-settled token rail would still need a settlement path in PaymentRouter; SpendGuard wired into the request path so budgets are enforced on-chain rather than in the client; and staking-weighted attestations with slashing, since today's score counts payments but stakes nothing.

Further out, the same 402 loop that prices an HTTP API prices inference and storage — making agent-to-agent payment, not just agent-to-API, the next step. Every wrapped service deepens one shared registry, and that graph cannot be forked without the payment history behind it.
